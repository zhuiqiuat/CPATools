# CPATools

程序设计团体赛（5 人队）赛后的**成绩统计工具**：把 PTA 成绩导出表、到梦空间活动参与名单、比赛报名表三份 Excel 合成一份结果——
按队伍算总分与总用时、分组排名、判定谁有奖、谁只拿入围分，最后直接导出可交给老师的**入围名单**与**颁奖名单**。

> 背景：协会办完一场团体赛，成绩在 PTA、报名在报名表、签到在到梦空间，三份表对不上，
> 人工核对一次要几个人花一晚上，还容易错。这个工具把这一步变成「放好三个文件，跑一次」。

## 功能

- **成绩导入**：读取 PTA 导出的成绩表，容错处理 `缺考`（记 0 分、不占入围资格）
- **名单交叉核对**：用「姓名 + 学号」把 PTA 成绩、报名表、到梦空间签到名单关联起来，只统计真正参赛的人
- **合并单元格回填**：报名表里「队名」是合并单元格，借助 EasyExcel 的 `MERGE` 事件把队名回填到该组每一行
- **组队聚合**：按队名聚合成队伍，单个队名最多 5 人
- **分组排名**：含**信息工程学院**成员的队伍进「信工院组」，其余进「外院组」，两组各自独立排名
- **并列处理**：同分时按总用时升序，用时短的靠前
- **奖项判定**：各组前 11 名的队伍中，个人得分占队伍总分 **≥ 10%** 的成员才有奖（避免 0 分躺赢），未获奖但考了正分的人进「入围名单」
- **名次映射**：队伍名次 → 奖项等级编码（1→1；2/3→2；4–6→3；≥7→4），编码含义由赛事奖励办法决定
- **结果导出**：两个 sheet 直接写成 `.xlsx`，交给赛事负责人发奖与录入学分

## 技术栈

| 项 | 选型 |
|---|---|
| 语言 | Java 23（`maven.compiler.source=23`） |
| 构建 | Maven |
| Excel | Alibaba **EasyExcel 4.0.3**（流式读 + 注解写，避免 POI 全量加载） |
| 依赖 | 仅 EasyExcel，无 Spring、无数据库 |

## 处理流程

```
PTA 成绩表 (.xlsx)  ─┐
到梦空间名单 (.xls) ─┼─→ 按「姓名+学号」关联 ─→ 报名表 (.xlsx) 组队
报名表 (.xlsx)      ─┘                            │
                                                  ▼
                                  分「信工院组 / 外院组」
                                                  │
                                    组内排序：总分 ↓，总用时 ↑
                                                  │
                          前 11 名队伍中「个人分占比 ≥ 10%」的成员
                                                  │
                     ┌────────────────────────────┴───────────────┐
                     ▼                                            ▼
             颁奖名单（含奖项等级）                     入围名单（未获奖但得分 > 0）
```

## 输入文件格式

工具按**表头名**映射列（EasyExcel `@ExcelProperty`），列名或表头行数变动会直接读不到数据。

**1. PTA 成绩导出（`.xlsx`，表头 3 行）**

| 学号/邮箱、电话 | 姓名/昵称 | 总分(200.0) | 耗时(秒) |
|---|---|---|---|
| 20240001 | 张三 | 120 | 9860 |

> `缺考` 会被识别为 0 分。

**2. 到梦空间「活动参与名单导出（个人）」（`.xls`，表头 1 行）**

| 姓名 | 学号 | 院系 | 班级 |
|---|---|---|---|
| 张三 | 20240001 | 信息工程学院 | 24计科本1 |

> `院系 == 信息工程学院` 即标记为信工院，用于分组。

**3. 比赛报名表（`.xlsx`，表头 2 行，读 sheet0 + sheet1）**

| 队名（合并单元格） | 学号 | 姓名 |
|---|---|---|
| 示例1队 | 20240001 | 张三 |

> 同一个队名最多收 5 人，超出会另起一队。

**4. 通过名单（`.xlsx`，表头 1 行）** — `checkDMKJ` 阶段的产物，作为 `calculateRank` 的组队输入

| 队伍 | 学号 | 姓名 |
|---|---|---|

## 输出文件

| 文件 | 内容 | 字段 |
|---|---|---|
| 颁奖名单.xlsx | 获奖人员 | 排名（奖项等级）/ 学号 / 姓名 |
| 入围名单.xlsx | 参赛但未获奖 | 班级 / 学号 / 姓名（按姓名排序） |

## 快速开始

```bash
git clone https://github.com/zhuiqiuat/CPATools.git
cd CPATools
mvn -q compile
mvn -q exec:java -Dexec.mainClass=top.ZQAT.CPATools.Main
```

**运行前**需要改三处路径（当前硬编码在源码里，见「已知限制」）：

| 位置 | 变量 | 指向 |
|---|---|---|
| `ReadPTA.java` | `filename` | PTA 成绩导出表 |
| `ReadDMKJ.java` | `filename` | 到梦空间活动参与名单 |
| `ReadTeam.java` | `filename` | 比赛报名表 |
| `Main.java` | `creditfile` / `rewardfile` / `outfile` | 输出路径 |

两种运行流程通过 `Main.main()` 里的注释切换：

```java
public static void main(String[] args){
//        checkDMKJ();   // ① 报名表 + 到梦空间 → 通过名单（筛出满 5 人且签到的队伍）
        calculateRank();  // ② 通过名单 + PTA 成绩 → 入围名单 + 颁奖名单
}
```

## 目录结构

```
src/main/java/top/ZQAT/CPATools/
├── Main.java          # 两个入口：checkDMKJ / calculateRank，排序与奖项判定逻辑
├── Person.java        # 个人：学号/姓名/班级/得分/用时/是否获奖/是否入围/是否信工院/队伍名次
├── Team.java          # 队伍：队名/成员/总分/总用时/名次
├── ReadPTA.java       # 读 PTA 成绩表
├── ReadDMKJ.java      # 读到梦空间名单，回填班级与院系
├── ReadTeam.java      # 读报名表（含合并单元格回填）、按队名聚合
└── Excel*.java        # EasyExcel 读写映射（ExcelPTA/DMKJ/Team/Team2/Rank/Reward/Credit/Member）
```

## 已知限制

1. **路径硬编码**：输入输出路径写死在源码里（`G:\...`），换机器必须改代码；计划改为命令行参数或 `config.properties`。
2. **流程靠注释切换**：`main()` 里注释掉一行来选流程，容易漏改。
3. **排序比较器不一致**：两队分数与用时完全相同时 `compare` 返回 `-1`（应返回 `0`），极端情况下排序结果不稳定。
4. **无异常处理**：缺文件、表头改名、成绩列出现非数字都会直接抛异常，命令行只看到堆栈。
5. **依赖表头精确匹配**：列名（如 `总分(200.0)`）随 PTA 导出模板变化，需同步改 `@ExcelProperty`。
6. **无单元测试**：排序与奖项判定是纯函数逻辑，值得补 JUnit 覆盖。
